Production testing is therefore deliberately paused until Vercel serves a new Watch chunk for commit `fa7e5a7`.

Vercel subsequently reported success for commit `fa7e5a7`. A fresh cache-busted Attack on Titan route rendered the player again, but the first post-deployment visual capture was still waiting for metadata (`00:00 / 00:00`). The next probe will verify the served chunk code and wait for the player to report an actual media duration before measuring continuity.

The deployed chunk is now `Watch-Bd2770zi.js`. Its compiled player code calls `F.off("video:error")` immediately after ArtPlayer construction, does not contain the legacy `hls.startLoad()` restart, and does not treat `502` as a terminal signed-URL status. The live media element then reached `readyState: 4` with the full 25:40 VOD range buffered. A passive event probe was attached before starting user-gesture playback; ArtPlayer resumed the prior recorded position at `11:21` rather than reconnecting from the beginning.

The live VOD observation remained continuous. From the history-resume seek at `681.86` seconds, playback advanced to `743.38` seconds with `readyState: 4`, `paused: false`, and the complete range (`0` through `1540.99`) still buffered. The captured event list contains only the expected one-time history seek, `canplay`, and `playing`; it contains no `error`, `stalled`, `emptied`, `pause`, or source-reset/reconnect event. The 30-second wait call exceeded the browser action limit, but its subsequent metric retrieval captured approximately 61.5 seconds of actual uninterrupted playback.

The live route then switched from Ally to Kiwi while preserving playback around 12:53. Kiwi continued at `785.91` seconds with `readyState: 4`, `paused: false`, and the full VOD range buffered. As with Ally, this resolver result used a native-media path (`art.hls` absent), so it validates the removal of ArtPlayer's reconnect reset on two live providers but does not instantiate the hls.js branch. The hls.js retry path is validated by the focused policy regression test and the deployed compiled Watch code.

The subsequent Kiwi observation exposed a second continuity defect: a native-media error caused an expected source refresh, but `loadStream` cleared `pendingResumeRef` before the rebuilt player reached `canplay`. The player then restarted at zero. The follow-up local correction now captures a safe current position before same-provider refresh or provider failover, keeps that handoff through `loadStream`, applies it exactly once at `video:canplay`, and clears it only for an actual episode change.
